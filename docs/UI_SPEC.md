# PulseProof UI specification

The initial concept at `docs/pulseproof-ui-concept.png` is the visual reference. The implementation intentionally replaces its invented banks, currency and metrics with the official Hack.Genesis public dataset.

## Design system

- Background: true near-black navy `#050b10`; surfaces `#09131b` and `#0c1822`; no glass blur or purple.
- Text: `#edf7fb`; secondary `#8799a5`; dim `#50616d`.
- Signal cyan: `#18d5ff`; success lime: `#72f05a`; pending amber: `#ffb020`; failure coral: `#ff5263`.
- Geometry: open panels separated by one-pixel rules; 10px radii only on functional regions and controls.
- Typography: system grotesk for readable UI, system monospace for ids, hashes, values and event labels.
- Motion: a restrained moving pulse on the active lifecycle rail; disabled under `prefers-reduced-motion`.

## Primary screen inventory

- Left rail: PulseProof mark; Live routing, Replay arena, Decisions, Policy, Validation; runtime status.
- Command bar: `LIVE ROUTING`, deterministic policy hash, strict release state, `Run demo`.
- Event stream: ten official operations, amount, bank, selected provider and lifecycle state.
- Current-operation canvas: `Snapshot → Hard Gate → Vector Deficit → Reserve → Reconcile`.
- Provider rails: target versus actual count share and current debt.
- Decision Proof: hard exclusions, winner/runner-up, debt before/after, reservation and event-chain hash.
- Shadow Replay: exact same queue under deterministic weighted random, conversion-first and PulseProof.
- Chaos control: switches to a real scripted timeout → late cancel → release → reroute run generated by the Ruby engine.

## Responsive behavior

- Desktop ≥1180px: fixed sidebar, event table, two-column decision/proof region, three replay charts.
- Tablet 760–1179px: compact sidebar, decision/proof stack, replay horizontal scroll.
- Mobile <760px: top navigation strip, event rows collapse to three compact lines with a lifecycle rail, panels stack, controls remain reachable.
