## Intentional differences

- The reference places the exceptional payout first for immediate storytelling. The implementation keeps `op_106` sixth because the official chronological queue and its preceding state are part of the proof; the Chaos view opens on it by default.
- ViPay is labelled **«Освобождён»**, not **«Исключён»**. A confirmed cancellation releases its reservation; it does not make the provider globally invalid.
- The implementation says **«Безопасный fallback»**, not “most reliable provider”. The available history does not justify inventing that claim.
- Reference placeholder scores were replaced by engine-generated values: target deviation and expected settlement on the same queue.
- The traffic share moves only after QuickPay accepts the payout, because QA clarified that `traffic_percentage` is counted by the final provider after fallback.
- The proof area gained real copy/export actions. This is a product enhancement, not a decorative deviation.

## Copy audit

- No rupees, Indian banks, fabricated QPS/p95/error telemetry or unverified capability claims remain.
- Every number visible in the main view comes from `demo-data.json`, which is generated by the same Ruby engine as the submission files.
- Operational language distinguishes timeout, confirmed cancellation, reservation release and approval; these states are never collapsed into a generic failure.
- The interface explicitly says the router processes a current snapshot and does not see future operations.

## Verification record

- Desktop visual pass was completed against a `1600 × 1000` CSS viewport before the final copy/export enhancement; the supplied screenshot is rasterized by the in-app browser at `800 × 500`.
- The accepted concept and the verified render were both visually inspected at source size.

- Remaining deliberate difference: the browser screenshot predates the final synchronized phase copy, click-to-scrub route and proof-export buttons; layout geometry is unchanged and all additions pass lint and production build.
